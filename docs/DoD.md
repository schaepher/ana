# DoD：交付验收清单 + 五轴自检（Q235，2026-08-22）

借鉴 GitNexus「DoD 9 大项 + AI 五轴自检」成文。把既有约定（测试先行、
验证矩阵、形态矩阵、自建小示例、改完验证后 push）统一为交付前逐项
自查清单。**开发流程（test-first）是硬流程；本清单是收尾检查。**

## 交付前逐项自查

1. **测试先行**：先写测试再实现再执行（红线确认失败）；测试覆盖
   形态矩阵（起点 × 传递 × 写入变体）与真实运行路径；验证用自建
   小示例（秒级）+ 命令设超时
2. **正确性**：真实仓库验证（go2o 15 万节点）；边界输入（空库/
   非法参数/超时）；幂等（重跑/增量不重复）；外部依赖（ORM 形态）
   主动构造真实模块验证
3. **契约兼容**：改动涉及多路径（内存 BFS / SQL 路径 / CLI / API /
   前端）时全部同步——Q212/Q218/Q234 教训：两条路径判定不一致
   = bug；共享逻辑放共享函数不复制
4. **架构一致**：六边形分层（domain → port → adapter）；改动落在
   正确层（查询编排在 action，存储细节在 sqlite，展示在 cli/server）
5. **可读性**：文件 ≤300 行（line-limit skill）；注释说明「为什么」
   非「是什么」；Q 编号注释引用设计文档对应节
6. **性能**：大仓库实测（go2o）；查询设超时；BFS/递归有深度上限；
   新增热路径（打开/加载）测耗时增量
7. **安全**：无密钥/私有仓库名落库；fixture 表名脱敏（中性名勿还原）；
   不引入注入面
8. **可回滚**：脚本操作前 dry-run；git 提交原子（一个功能一个提交）；
   文档与代码同 commit；回滚路径明确（git checkout / 重建索引）
9. **文档落档**：field_trace.md 加 Q 节（设计先行：先写设计再实施）；
   skill/AGENTS.md/runbook 同步更新
10. **推送**：验证全绿后 `git push`（不留未推提交）

## 五轴自检（变更完成后快速过一遍）

- **正确性**：真实验证过，不靠「应该没问题」
- **可读性**：下一个人（或 3 个月后的自己）能看懂为什么
- **架构一致性**：放在正确层，没有复制粘贴的判定逻辑
- **安全性**：无秘密、无注入、fixture 无真实业务名
- **性能**：大仓库实测或推理过量级，未引入无界查询

任一项不确定即补验证，不自评通过。
